# 접근 미니게임 물리 리디자인

## 배경과 목적

최종 접근 미니게임(착륙/궤도 진입)을 구현해서 병합한 뒤, 사용자가 직접
플레이해보고 "너무 단순해서 실망스럽다"고 평가했다. 사용자가 원하는
방향은 진짜 물리 시뮬레이션에 가까운 조작감이다:

- 착륙: 역분사 로켓을 아래·좌·우로 조정해 발사하면서 목표 지점에
  안착하는 형태.
- 궤도 진입: 중력 개념을 적용하고 추진/역추진으로 적절한 궤도에
  들어가게 만드는 형태.

이 문서는 **미니게임의 내부 구현(물리·조작·시각화)만** 다시 설계한다.
이전 스펙([[approach-minigame-design]])이 정한 상위 통합 계약 — 미니게임
결과가 곧 탐사 성공/실패를 결정하고, 장비는 자격 게이트 + 미니게임
난이도 완화로만 작용하며, 암석형=착륙/가스-얼음 거대행성=궤도 진입으로
나뉜다는 것 — 은 그대로 유지한다.

## 유지되는 것 (이전 스펙에서 변경 없음)

- 미니게임 결과가 그대로 탐사 성공/실패가 됨 — 확률 굴리기 없음.
- 우주선 단계 + (가스 행성은) 탐사선 2단계 게이트는 그대로.
- 재도전 무비용.
- 실패 문구는 미니게임에서 실제로 무엇이 잘못됐는지에 맞춰 보여줌.

## 목표

- **착륙**: 2D 운동(위치·속도, 중력 + 3방향 추력)으로, 화면 중앙 기준
  좌우 랜덤 위치에서 하강을 시작해 중앙의 목표 지점에 안전한 속도로
  안착시킨다.
- **궤도 진입**: 궤도 반경을 1축 운동(반경·반경 변화 속도, 순행/역행
  추력)으로 다뤄, 반경을 목표 범위 안으로 가져오고 변화 속도도 0에
  가깝게 만들어야("진짜로 원궤도에 안착") 성공한다.
- 두 미니게임 모두 연료가 한정되어 있다 — 방향키를 누르고 있는 동안
  소모되고, 떨어지면 그 뒤로는 조작이 불가능하다.
- 기존 부품 3종(추진 부스터/생명유지 모듈/정밀 관측 장비)의 효과를 이
  미니게임에 맞게 다시 배정한다 — **새 아이템은 추가하지 않는다.**
- 방향키(위/아래/왼쪽/오른쪽)로 두 미니게임을 공통 조작한다.
- 지금의 퍼센트 바(DOM) 대신 캔버스로 부드럽게 렌더링한다.

## 비목표

- 진짜 궤도역학(타원 궤도, 각운동량, 역제곱 중력 법칙, 근점/원점)은
  시뮬레이션하지 않는다 — 사용자가 "궤도 형태는 간단하게 원궤도로
  한정"하자고 명시적으로 정함. 궤도 반경은 착륙의 "고도"와 구조적으로
  동일한 1축 운동으로 다룬다.
- 회전·충돌 메시 같은 강체 물리(리지드바디 엔진)는 넣지 않는다 —
  점질량 운동방정식(가속도→속도→위치 적분) 수준으로 한정한다.
- 새 npm 의존성(물리 엔진 라이브러리 등)을 추가하지 않는다 — 직접
  적분한다.
- 새 아이템/부품을 추가하지 않는다 — 기존 3종의 효과만 재배정한다.

## 안티 목표

- 조작이 너무 복잡해서 중학생이 포기하면 안 된다 — 방향키는 미니게임당
  최대 3개로 제한하고, 목표 범위는 "넉넉하게" 둔다(사용자가 궤도 진입
  판정을 더 까다롭게 하는 대신 명시적으로 요청한 보상).
- 이번 기능에서 이미 확립한 원칙(미니게임 내용과 실패 문구가 일치해야
  함, 결과가 장비 기반 확률과 무관하게 플레이로만 정해짐)을 깨면 안
  된다.

## 결정된 설계

### 공용 조작/연료

- 방향키만 쓴다: 위/아래/왼쪽/오른쪽.
- 방향키 중 하나 이상이 눌려 있으면 연료가 초당 일정량 소모된다 —
  **동시에 몇 개를 누르고 있든 소모량은 하나 누른 것과 같다**(합산하지
  않음). 연료가 0이 되면 그 즉시 모든 추력이 0이 되어(조작 완전 불가)
  중력/관성에만 내맡겨진다.
- 착륙과 궤도 진입은 같은 "최대 연료" 공식(장비로 정해짐)을 공유한다.

### 부품 효과 재배정 (새 아이템 없음)

- **추진 부스터**: 최대 연료량을 크게 늘림 (주 연료 보너스).
- **생명유지 모듈**: 기존 "이중 안전장치" 플레이버에 맞춰 최대 연료량을
  조금 더 늘림 (보조 연료 보너스, 부스터와 중첩).
- **정밀 관측 장비**: 기존 "정밀 접근" 플레이버에 맞춰 목표 범위(착륙
  지점 폭 / 궤도 허용 반경 범위)를 넓힘.

(정확한 수치는 플랜 단계에서 정한다.)

### 착륙 — 2D 운동

- 상태: 위치 `(x, y)`, 속도 `(vx, vy)`.
- 중력이 매 프레임 `vy`를 증가시킨다(아래로 가속).
- 추력: **위** 방향키 = 아래쪽 역분사 = `vy` 감소(감속). **왼쪽/오른쪽**
  방향키 = 그 방향키가 가리키는 쪽으로 `vx` 변화(분사구 방향이 아니라
  "방향키를 누르면 그쪽으로 움직인다"는 직관을 우선한 매핑 — 사용자가
  "역분사 로켓을 좌/우로"라고 표현한 걸 플레이어 조작감 기준으로
  해석한 것. 다르게 쓰고 싶으면 말해달라.)
- 시작 위치: 화면 중앙 기준 랜덤 좌우 오프셋, 화면 상단 부근. 목표
  지점: 화면 중앙 하단의 고정된 착륙 지점(폭이 있는 범위).
- 캔버스/뷰포트는 고정이다(카메라가 따라가지 않음). `x`는 캔버스
  좌우 가장자리에서 더 못 나가게 클램프한다 — 가장자리에 닿아도
  실패 처리하지 않고, 속도만 0으로 죽이거나 가장자리에 머무르게 해서
  플레이어가 다시 안쪽으로 조작할 수 있게 한다.
- 판정(지면에 닿는 순간):
  - `|x - 목표중심| > 허용폭/2` → 실패("목표 지점을 벗어났습니다" 계열).
  - 착지 속도가 안전 속도를 초과 → 실패("충돌했습니다" 계열).
  - 둘 다 만족 → 성공.
  - 연료가 떨어진 채 착지 전이고 제한 시간에 도달 → 실패("연료
    소진" 계열) — 연료가 없어도 중력으로 결국 땅에 닿으므로, 이건
    비정상적으로 오래 걸리는 경우에 대한 안전장치 성격이 크다.

### 궤도 진입 — 1축 운동(반경)

- 상태: 반경 `radius`, 반경 변화 속도 `radialSpeed`.
- 시작: 반경이 목표보다 큰 값에서 시작한다 ("처음 속도가 너무 빨라
  궤도가 목표보다 커진" 상황을 반경으로 직접 표현).
- 추력: **아래**(역행 분사) = 반경이 줄어드는 쪽으로 가속. **위**(순행
  분사) = 반경이 커지는 쪽으로 가속. 왼쪽/오른쪽은 쓰지 않는다. 자유
  낙하에 해당하는 "중력" 항은 없다 — 가만히 두면 그 순간의
  `radialSpeed`가 관성으로 유지될 뿐이다.
- 판정: 매 프레임 "반경이 목표 범위 안 **그리고** `|radialSpeed|`가
  허용치 미만"을 확인해 둘 다 만족하는 순간 성공.
  - 반경이 행성 충돌 임계값 이하로 떨어지면 즉시 실패("충돌" 계열).
  - 연료가 떨어진 채 아직 조건을 만족하지 못한 상태로 제한 시간에
    도달하면 실패("연료 소진" 계열).

### 시각화 (캔버스)

- 두 미니게임 모두 기존 다크 글래스 HUD 톤을 유지하되, DOM 퍼센트 바
  대신 `<canvas>`에 직접 그린다. 새 라이브러리 없이 Canvas 2D API만
  쓴다.
- 착륙: 하늘/땅 배경, 화면 하단 중앙에 목표 폭 표시, 탐사선 아이콘이
  실시간 위치로 그려짐. 철강빛 남색 + 호박 팔레트(기존 착륙 팔레트와
  동일 계열) 유지.
- 궤도 진입: 중앙에 행성, 목표 반경을 고리(annulus)로 표시, 탐사선을
  나타내는 점이 현재 반경을 따라 원을 그리며 돈다(각도 회전은 장식용,
  실제 판정에는 반경만 쓰임). 청록 팔레트(기존과 동일 계열) 유지.

## 제약

- 새 npm 의존성 없음(물리 엔진 라이브러리 포함).
- 세미콜론 없이, 홑따옴표.
- 상위 통합 계약(판별 유니언 `ApproachResult` 구조, `resolveMission`
  연동, 장비 게이트, 비행 연출 타이밍)은 바꾸지 않는다 —
  `ApproachFailureReason`의 구체적인 값들만 이번 미니게임 내용에 맞게
  다시 정의한다.
- 방향키는 미니게임당 최대 3개(착륙: 위/왼쪽/오른쪽, 궤도 진입:
  위/아래)로 제한한다.

## 구현자에게 맡기는 부분

- 정확한 수치: 중력 가속도, 각 추력의 크기, 연료 소모율/최대 용량,
  착륙 허용폭/안전 속도, 궤도 허용 범위/허용 변화속도, 충돌 임계
  반경, 제한 시간.
- 부품별 정확한 보너스 수치.
- 캔버스 렌더링 세부(아이콘 모양, 애니메이션 디테일).
- 파일 구성 — 기존 `approach-minigame-sim.ts`/`approach-minigame.ts`를
  이 내용으로 교체할지, 구조를 어떻게 나눌지.
